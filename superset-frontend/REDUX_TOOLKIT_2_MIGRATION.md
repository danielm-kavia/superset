# Redux Toolkit 2 migration record

## Completed compatible changes

The frontend manifest targets the Redux Toolkit 2 stack:

| Package | Target declaration |
| --- | --- |
| `@reduxjs/toolkit` | `^2.12.0` |
| `redux` | `^5.0.1` |
| `react-redux` | `^9.3.0` |
| `redux-thunk` | `^3.1.0` |

The application and test store factories use `configureStore` default middleware, which includes thunk middleware. The application store extends default enhancers through Redux Toolkit 2's enhancer callback, preserving its default enhancer tuple before adding the SQL Lab persistence enhancer.

React Redux typed hooks use the React Redux 9 `withTypes` API. The explicit `ThunkDispatch` intersection remains because `getMiddleware` is intentionally annotated as `ConfigureStoreOptions['middleware']`; that annotation erases the middleware tuple information otherwise used to infer thunk dispatch support. `redux-thunk` is therefore a direct dependency, rather than a type-only reliance on Redux Toolkit's transitive installation.

## Strict lockfile validation

The incompatible Ant Design 5-only JSON Forms renderer has been replaced with the local semantic renderer registry, and the frontend lockfile was regenerated by npm under Node `v24.16.0` and npm `11.13.0`. Both `CI=true npm install` and a clean `CI=true npm ci` completed without `--force` or `--legacy-peer-deps`.

`npm ls` and `npm ls --package-lock-only @reduxjs/toolkit react-redux redux redux-thunk` resolve the direct migrated stack as `@reduxjs/toolkit@2.12.0`, `react-redux@9.3.0`, `redux@5.0.1`, and `redux-thunk@3.1.0`. Unrelated transitive Redux 3/4 copies remain where required by their owning dependencies, but the root migrated stack is deduplicated to Redux 5.
